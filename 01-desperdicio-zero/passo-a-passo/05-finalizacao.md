# 5. Evolua sozinho

Feche o código de referência e execute uma história completa: cadastrar, listar,
filtrar, remover, sair e abrir novamente. Em cada etapa, preveja a saída antes de
olhar o terminal. Se depender de seguir o tutorial linha a linha, pratique mais
uma função pequena antes de acrescentar funcionalidades.

## Explique suas decisões

Por que a data é convertida? Qual a diferença entre vencido e próximo? Onde mora
o próximo ID? O que acontece se o salvamento falhar? Escolha uma dessas perguntas
e responda com um exemplo do seu programa, não apenas uma definição decorada.

## Personalize com um objetivo

Escolha um desafio em [desafios.md](../desafios.md). Escreva uma entrada e uma saída
esperadas, abra uma branch e altere uma coisa por vez. Não comece pelo desafio
mais difícil para parecer avançado: uma pesquisa correta com testes já demonstra
autonomia. Consulte [dicas.md](../dicas.md) só depois de registrar uma tentativa.

## Apresente sua versão

Seu README deve explicar para quem serve, como rodar, onde os dados ficam e quais
regras você mudou. Inclua uma demonstração de terminal com dados genéricos. Mantenha
a licença e dê crédito à base. Não publique seu arquivo real de alimentos.

Faça um commit como “Adiciona pesquisa por nome com teste de maiúsculas”. Uma mensagem
boa descreve comportamento, não “arrumei coisas”. Revise o [checklist](../checklist.md).

Você está pronto para o BuscaCEP quando consegue criar um registro validado, salvar,
ler e explicar um erro de arquivo. A diferença seguinte será receber dados de outro
computador, e não somente do teclado: [próximo projeto](../../02-buscacep/README.md).
